# Agents Anywhere 2.2.0

2.2.0 是一次接口更新（MINOR）：Go Server 新增**模型网关**，桌面上的 Claude Code 会话可以把模型请求经服务器路由到账号下自建的第三方供应商；同时新增供应商管理、设备默认路由、会话级路由、网关凭证与请求摘要等 `/api/v2` 接口。按[版本号规则](../versioning.md)，各端版本号统一升到 2.2.0。接口契约见 [Model Gateway & Provider Management API](../api/model-gateway.md)。

## 接口变化

- 新增 `/api/v2/model-providers` 的 CRUD 与 `POST /model-providers/{id}/check`。供应商密钥由服务端保存，任何接口、事件和日志都不返回明文，只用 `credentialConfigured` 表示是否已配置；`PATCH` 使用 `expectedRevision` 做并发保护（冲突返回 409），未传密钥表示保留，`clearCredential` 表示删除。
- 新增 `/api/v2/connectors/{connectorId}/model-route`（设备默认供应商）与 `/api/v2/sessions/{sessionId}/model-route`（会话级路由）。删除仍被引用的供应商需要显式 `force=true`；被删除供应商的显式路由显示为失败并等待重新选择，不会静默回落到其他供应商。
- 新增 `/api/v2/connectors/{connectorId}/model-route/gateway`（签发 / 撤销网关凭证）与 `/api/v2/model-route-operations/{id}`（查询 / 取消切换操作）。网关凭证只在签发时经 Connector 的已认证 WebSocket 下发一次，重复签发会轮换并立即作废旧凭证；电脑不在线时签发直接返回 409，避免把无法送达的新凭证写进服务器。
- 新增数据面 `/api/v2/gateway/v1/messages`、`/v1/messages/count_tokens`、`/v1/models`，使用网关凭证而不是用户日志令牌认证；请求体上限由 `AA_GATEWAY_MAX_BODY_BYTES`（默认 64 MiB）控制。网关只改写顶层 `model` 字段，其余请求内容原样透传；OpenAI 协议的供应商由服务端做双向转换（工具调用、图片、流式增量），不支持的 content 类型明确报错而不是静默丢弃。
- `GET /sessions/{id}/runtime/catalogs/model` 与连接器级对应接口现在返回账号下的模型供应商列表（`selectionId` 即供应商 ID，`metadata.routeState` 表示已生效 / 等回合结束 / 最近失败）；`PATCH /sessions/{id}/runtime/selections` 的 `model` 选择等同于会话路由切换。权限目录发布 `default`、`acceptEdits`、`plan`、`auto` 四项，但在缺乏已验证控制接口前全部标记为不可远程设置。
- 供应商检查分 `connect`（只探可达，不发送密钥，`authOk` 为 false）与 `request`（真实一次最小请求，同时验证认证，可能产生费用）。路由到已停用或未配置密钥的供应商会被拒绝（409），而不是接受后在请求时才失败。
- 会话能力集新增 `catalog.model` 与 `catalog.permission`，客户端按能力显示模型 / 权限选择入口。
- 新增实时事件 `runtime.catalog.updated`（`{catalogType, catalog}`），与 `runtime.state.updated` 在同一自增序号下发。
- `/api/v2/admin/service` 新增 `modelGateway` 聚合计数（请求、错误、流、字节，按供应商分组），不含任何提示词或密钥。
- Connector 新增 `gateway.config` RPC：接收 `{baseUrl, token, enabled}`，把 `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` 注入它打开的每个 Claude 终端；配置写入连接器数据目录（`gateway.json`，0600），不进入命令行、日志或插件共享目录。旧 Connector 不认识该方法，服务端会以 `pushed: false` 告知设备离线/不支持。
- 数据库新增迁移 `0017_model_gateway.sql`（供应商、设备默认、会话路由、切换操作、网关凭证、请求摘要）。

## 已知限制与未验证事项

按设计文档第 16 节，以下必须在真机环境核实后才能视为完成：

1. 当前 Claude Code 版本是否发送 `x-claude-code-session-id` / `x-claude-code-prompt-id`。网关在请求头缺失时按设备默认供应商处理并记为未绑定会话，不会冒认其他会话；但如果头缺失，会话级切换不会生效。
2. `ANTHROPIC_BASE_URL` 带 `/api/v2/gateway` 前缀与 Claude Code、nginx、上游路径拼接的兼容性。
3. 权限模式的读取 / 设置闭环：目前没有已验证的插件接口，四种模式仅作为目标值展示并标记不可远程切换。
4. 手工启动的终端不会自动接入网关；只有 Connector 打开的终端会带上网关环境变量。
5. 供应商密钥按用户要求以明文存放在 SQLite 中，数据库与备份的读取者可以看到；网关凭证与供应商密钥在公网传输前必须由 TLS（或等效受信通道）保护。
6. 第三方供应商的接口、认证、图片 / 工具 / thinking / 上下文能力和错误语义需要逐家验证；`check` 的 `request` 模式会产生真实费用。

## 数据库迁移

- `0017_model_gateway.sql`：新增 `model_providers`、`connector_model_defaults`、`session_model_routes`、`route_switch_operations`、`gateway_credentials`、`gateway_request_log` 六张表及索引。仅新增，不修改既有表结构；`aa-server` 启动时自动应用。
